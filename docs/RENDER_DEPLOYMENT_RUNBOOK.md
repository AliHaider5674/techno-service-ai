## Section 2: Pre-Flight Check (mandatory before deploy)

Three pre-deploy fixes are needed. **Do not skip these — the app will crash on Render without them.**

### 2.1 — `requirements.txt` is missing 2 production packages

The current `requirements.txt` was written for SQLite dev / testing only. Render uses PostgreSQL, and the encryption layer requires the `cryptography` library. Add these two lines to `requirements.txt`:

```diff
 jinja2==3.1.6
 python-multipart==0.0.20
+psycopg2-binary==2.9.10
+cryptography==46.0.1
```

**Suggested location:** append to the end of `requirements.txt`. Pinned versions match the test environment to avoid surprises.

**Commit message:** `build: add psycopg2-binary and cryptography to requirements.txt (pre-Render fix)`

**Why this is needed:**
- `psycopg2-binary` — PostgreSQL driver for SQLAlchemy. Without it, the app can't connect to the Render PostgreSQL.
- `cryptography` — used by the encryption layer (HD-PHASE8-004) for AES-256-GCM in SQLite fallback and for the SHA-256 key-derivation step.

**Verify locally after edit:**
```bash
pip install -r requirements.txt
```
Expected: 2 new packages install cleanly. No conflicts.

### 2.2 — `tsai_session` cookie requires `TSAI_COOKIE_SECURE=1` on HTTPS

By default the app sets cookies without the `Secure` flag. On `https://kuwaittsai.com` (HTTPS), browsers will REJECT a non-secure cookie, breaking sign-in. Set the env var in Render (Section 4.5 below).

### 2.3 — Schema is auto-applied on app startup

**No manual migration command needed.** The `create_app()` function in `src/techno_service_ai/app.py` line 176–178 has:

```python
@app.on_event("startup")
def _startup() -> None:
    apply_schema()
```

This creates all 98 entities, the 3 Constitutional Registers, the 3 Status dimensions, the audit log, and all immutability triggers — idempotently — every time the app boots. This is a deliberate design (no Alembic; no separate migration step).

**What this means for deploy:** When Render first boots the Web Service, the schema is created in ~2 seconds. The first sign-in then succeeds.

## Section 3: Environment Variables — Complete Table

The table below lists EVERY env var the app reads at runtime. **All values marked `[GENERATE]` must be generated by you; do NOT use the dev defaults in production.**

| # | Env Var | Required? | Source | Example / Dev Default | Production Value |
|---|---|---|---|---|---|
| 1 | `TSAI_DATABASE_URL` | **YES** | Render auto-injects from PostgreSQL `Internal Database URL` (Section 5) | `sqlite:///./data/tsai.db` | `postgresql://tsai_app:<PASSWORD>@dpg-xxx-a/tsai_prod` |
| 2 | `TSAI_JWT_SECRET` | **YES** | `[GENERATE]` — use `secrets.token_urlsafe(32)` (see 4.5) | dev: file fallback in `data/.jwt_secret` | 32+ char random string |
| 3 | `TSAI_ENCRYPTION_KEY` | **YES** | `[GENERATE]` — any non-empty string (used as AES-GCM key source + pgcrypto key) | dev: `dev-key-do-not-use-in-production-x` | 32+ char random string |
| 4 | `TSAI_COOKIE_SECURE` | **YES (on HTTPS)** | Set to `1` | dev: `0` | `1` |
| 5 | `TSAI_AUDIT_RETENTION` | **YES** | Set to `PERMANENT` (Constitution Article XX) | default: `PERMANENT` | `PERMANENT` |
| 6 | `TSAI_DEFAULT_ADMIN_PASSWORD` | **YES** | Set to a strong password you will remember (CHANGE IMMEDIATELY after first sign-in) | dev: `ChangeMe!2026` | a strong password (e.g., generated) |
| 7 | `TSAI_JWT_LIFETIME` | OPTIONAL | Token lifetime in seconds | `3600` (1 hour) | `3600` (default OK) |
| 8 | `TSAI_SESSION_LIFETIME` | OPTIONAL | Session cookie lifetime in seconds | `28800` (8 hours) | `28800` (default OK) |

**How to generate the secrets (run once on your Windows machine, in PowerShell):**

```powershell
python -c "import secrets; print('TSAI_JWT_SECRET=' + secrets.token_urlsafe(32))"
python -c "import secrets; print('TSAI_ENCRYPTION_KEY=' + secrets.token_urlsafe(32))"
python -c "import secrets; print('TSAI_DEFAULT_ADMIN_PASSWORD=' + secrets.token_urlsafe(16))"
```

Copy the printed values into Render's environment variables (Section 4.5).

## Section 10: Ongoing Operations

### 10.1 — Auto-deploy on git push

Render is configured to **auto-deploy on every `git push origin main`**. You don't need to click "Manual Deploy" again. The deployment log will show the new build, and the service will restart with the new code (and re-apply the schema — idempotent).

### 10.2 — Free-tier expiry

**PostgreSQL Free tier is 90 days.** Set a calendar reminder for 2026-10-20 to upgrade to `Starter` ($7/month) before it expires. After expiry, the database is deleted and you lose all data.

### 10.3 — Web Service free tier

**Web Service Free tier** spins down after 15 minutes of inactivity. First request after spin-down takes ~30 seconds (cold start). If you want always-on, upgrade to `Starter` ($7/month).

### 10.4 — Backups

- **Render paid plans** include automatic daily backups (retained 7 days).
- **Free tier has no automatic backups.** Set up a cron job OR do a manual `pg_dump` weekly.

Manual backup:
```bash
# In Render Shell of the Web Service
pg_dump $TSAI_DATABASE_URL > /tmp/backup_$(date +%Y%m%d).sql
# Then download /tmp/backup_YYYYMMDD.sql via the Shell's "Download" button
```

### 10.5 — Monitoring

Render provides basic uptime monitoring. For deeper metrics (latency, error rate, request volume), upgrade to `Standard` plan ($25/month) or use an external tool (UptimeRobot, free, recommended).

### 10.6 — Rollback

If a deployment breaks the app:
1. Web Service → **"Events"** → find the previous successful deploy
2. Click **"Rollback to this deploy"** → confirm

The schema is idempotent, so an old-version rollback won't break a newer database (as long as the new schema additions are backwards-compatible — true for the current code).

## Section 12: Rollback Plan (if something goes wrong)

| Symptom | Likely cause | Fix |
|---|---|---|
| App crashes on startup, "ModuleNotFoundError: No module named 'psycopg2'" | Pre-flight fix 2.1 not applied | Add `psycopg2-binary` to `requirements.txt`, commit, push |
| Sign-in fails with 401 after entering password | `TSAI_COOKIE_SECURE` is not `1` on HTTPS | Set env var to `1`, save, wait for redeploy |
| Audit log entries are plaintext | `TSAI_ENCRYPTION_KEY` env var is empty | Set to a non-empty value, save, wait for redeploy |
| Database connection error | `TSAI_DATABASE_URL` is wrong or pointing to External URL | Use **Internal** Database URL, not External |
| Custom domain 404s | DNS not yet propagated | Wait 30 min, re-check |
| Custom domain serves HTTP not HTTPS | Render hasn't issued Let's Encrypt yet | Wait 30 min, re-check; if still HTTP, click "Verify" in Custom Domain settings |
| App slow on first request after inactivity | Free tier cold start | Upgrade to Starter $7/month |
